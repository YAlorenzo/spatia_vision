# SpatiaVision

Мобильный ассистент пространственной навигации для слабовидящих. Телефон снимает
окружение камерой, сервер находит препятствия и оценивает расстояние до них в метрах,
а телефон сообщает о них **пространственным звуком** (сигнал слышно с той стороны,
где препятствие) и **голосом** («Человек прямо, 3 метра», «Осторожно! Машина приближается слева»).

```
Телефон (браузер)                                   Сервер (ноутбук с GPU)
┌──────────────────────┐   кадр JPEG ~30 КБ        ┌──────────────────────────────────┐
│ камера → кадр 640px  │ ────────────────────────> │ Depth Anything V2 → глубина в м  │
│                      │      WebSocket /ws        │  ├ пол (RANSAC) → всё, что выше  │
│ 3D-звук (HRTF),      │ <──────────────────────── │  │  пола = препятствие (без класса)│
│ голос, рамки         │   JSON: препятствия       │ YOLO11 → люди, транспорт, животные│
└──────────────────────┘                           │  └ трекинг → скорость сближения  │
                                                   └──────────────────────────────────┘
```

## Быстрый старт

### Что нужно установить

| Что | Зачем | Где взять |
|---|---|---|
| Git | клонировать репозиторий | https://git-scm.com |
| Node.js 20+ | собрать фронт | https://nodejs.org |
| uv | Python и зависимости сервера | `winget install astral-sh.uv` |
| cloudflared | HTTPS-адрес для телефона | `winget install Cloudflare.cloudflared` |
| Видеокарта NVIDIA | желательно; без неё работает, но медленно | — |

> После `winget install` **полностью перезапусти VS Code / терминал**, иначе новые
> команды не найдутся. Если `cloudflared` всё равно не находится — запускай по полному
> пути: `"/c/Program Files (x86)/cloudflared/cloudflared.exe"`.

Все команды ниже — для **Git Bash** (в VS Code: панель терминала → `˅` → Git Bash).

### 1. Клонировать

```bash
git clone https://github.com/YAlorenzo/spatia_vision.git
cd spatia_vision
```

### 2. Сервер (один раз)

```bash
cd server
uv venv --python 3.12

# PyTorch с CUDA (для видеокарты NVIDIA):
uv pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
# ...или без видеокарты (будет ~1-2 кадра в секунду):
# uv pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu

uv pip install -r requirements.txt
cd ..
```

Модели скачиваются сами при первом запуске (YOLO11s ~19 МБ, Depth Anything ~100 МБ) —
первый старт сервера займёт минуту-две.

### 3. Фронт (один раз и после каждого изменения фронта)

```bash
cd mobile
npm install
npm run build:web      # собирает веб-версию в mobile/dist — её раздаёт сервер
cd ..
```

### 4. Запуск — два терминала

**Терминал 1 — сервер:**
```bash
cd server
.venv/Scripts/python -m uvicorn app:app --host 0.0.0.0 --port 8000
```
Ждём строку `[server] модели загружены, жду подключений на /ws`.

**Терминал 2 — туннель:**
```bash
cloudflared tunnel --url http://localhost:8000
```
В выводе будет рамка с адресом вида `https://какие-то-слова.trycloudflare.com`.

### 5. Открыть на телефоне

Открой этот `https://…trycloudflare.com` адрес в браузере телефона → **Начать** →
разреши доступ к камере. **Надень наушники** — звук объёмный, сторону лучше слышно в них.
Наведи камеру на людей, машины, деревья, стены — появятся рамки с расстоянием
(пунктир — препятствие без класса), внизу — ближайшее препятствие, зазвучат сигналы и голос.

Сверху:
- **Улица / Помещение** — выбирай под реальную сцену, от этого зависит модель глубины;
- **Звук / Голос / Вибро** — включить/выключить сигналы, голосовые подсказки и вибрацию;
- жёлтые плашки — обстановка и советы: «Толпа слева», «Парковка — осторожно», «Поднимите телефон выше».

> На iPhone звук может не играть, если включён беззвучный режим (переключатель сбоку).
> Вибрация работает в Chrome на Android; Safari на iPhone её не поддерживает.

**Остановка:** `Ctrl+C` в обоих терминалах.

## Почему именно так

- **Камера в браузере работает только по HTTPS.** Поэтому нужен туннель, а не просто IP ноутбука.
- **Один адрес на всё.** Сервер сам раздаёт собранный фронт (`mobile/dist`), и фронт
  подключается к `wss://<тот же адрес>/ws`. Ничего настраивать не нужно, работает в любой
  Wi-Fi сети (в т.ч. университетской, где устройства не видят друг друга).
- **Адрес cloudflared меняется при каждом запуске** — просто открывай новый.
- **Изменил фронт** → `npm run build:web` в `mobile/` и обнови страницу на телефоне.
  Сервер перезапускать не нужно (кроме случая, когда `mobile/dist` не было при его запуске).

## Другие способы запуска

### На ноутбуке с веб-камерой (удобно при разработке фронта)

Изменения кода фронта применяются сразу, без пересборки.

```bash
# Терминал 1
cd server && .venv/Scripts/python -m uvicorn app:app --host 0.0.0.0 --port 8000
# Терминал 2
cd mobile && npx expo start --web
```
Открыть `http://localhost:8081` — фронт сам найдёт сервер на порту 8000.

### Фронт через `expo start --tunnel` (два туннеля)

Если нужен hot reload прямо на телефоне: запусти сервер и `cloudflared` как выше, затем

```bash
cd mobile
echo "EXPO_PUBLIC_SERVER_URL=wss://АДРЕС-ОТ-CLOUDFLARED.trycloudflare.com/ws" > .env.local
npx expo start -c --tunnel
```
и открой на телефоне адрес, который выдаст **Expo**. Адрес в `.env.local` придётся
обновлять при каждом перезапуске cloudflared.

### Только распознавание, без телефона

```bash
cd server
.venv/Scripts/python tools/run_video.py --live --video 0 --indoor        # веб-камера ноутбука
.venv/Scripts/python tools/run_video.py --live --video путь/к/видео.mp4   # любое видео
.venv/Scripts/python tools/run_video.py --video видео.mp4                # без окна → output/<имя>/
```
Окно: слева кадр с рамками, справа карта глубины (светлее = ближе). Выход — `q`.
Зелёная заливка — найденный пол, фиолетовая — препятствия по глубине.
В подписи рамки `d=` — расстояние по модели глубины, `g=` — по размеру объекта,
`->1.2m/s ttc 3s` — скорость сближения и время до столкновения, `MOVING` — едет сам.
Внизу — высота и наклон камеры, оценённые по полу.
Флаги: `--indoor` (помещение), `--hfov 70` (угол обзора камеры), `--show` (каждый кадр, без пропусков).

Без окна сохраняются `annotated.mp4`, `objects.csv` (дистанция каждого объекта на
каждом кадре) и `summary.json` (FPS, стабильность).

### Проверить сервер без фронта

```bash
.venv/Scripts/python tools/ws_client.py --video 0 --seconds 20
```
Шлёт кадры по тому же протоколу, что и телефон, и печатает частоту и задержку.

## Как это работает

**Распознавание (сервер).** Два источника препятствий:

*А. Всё статичное — по карте глубины, без классов* (`free_space.py`). Дереву, столбу
и стене название не нужно — важно, что это препятствие.
1. **Depth Anything V2 Metric** строит карту глубины сразу в метрах (модели Outdoor / Indoor).
2. Карта переводится в 3D-облако точек (угол обзора — по длинной стороне кадра, поэтому
   одинаково для вертикального и горизонтального телефона), **RANSAC** находит плоскость пола —
   заодно известны высота и наклон камеры. Если пол пропал из кадра (вплотную к стене),
   держится последняя найденная плоскость.
3. Всё, что выше пола на 0.25–2 м и ближе 7 м, — препятствие (включая ветки на уровне головы).
   Зоны — **в метрах**: коридор движения шириной 0.9 м прямо по курсу и полосы до 2 м по бокам.

*Б. То, что может двигаться, — детектором* (`detection.py`): люди, транспорт, животные.
1. **YOLO11s** + **ByteTrack** (стабильный ID между кадрами).
2. Расстояние: глубина внутри рамки (30-й перцентиль — отсекает фон) + **геометрия** по
   известной высоте (человек 1.7 м, машина 1.5 м). При расхождении вес смещается к меньшей
   оценке. По этим же объектам **автокалибруется** масштаб модели глубины.

*В. Движение* (`motion.py`).
- **Скорость пользователя** — визуальная одометрия по полу: точки асфальта отслеживаются между
  кадрами (оптический поток), и раз плоскость пола известна, их смещение переводится в метры.
  Плюс «голосование» по кажущемуся сближению неподвижных объектов. Так различаются «стою»,
  «иду вперёд» и «пячусь назад».
- **Собственная скорость объекта** = его сближение минус скорость пользователя. Если ты идёшь
  к стоящей машине — она не «едет»; отходишь назад — ничего не «приближается».
  Для людей считается, что пользователь идёт не медленнее 1.2 м/с (по картинке скорость бывает
  занижена — ночью, на блестящем полу), «бежит» — быстрее 2.5 м/с.
- Скорость **не оценивается**: по рамкам, обрезанным левым/правым краем кадра (проходишь мимо
  припаркованной машины — видимая часть меняется, и стоящая машина «едет»); через скачок
  дистанции больше 15% за кадр (в толпе человека заслонили / трекер перепутал соседей).

*Наклон телефона.* «Вперёд/вбок» считаются в **земных осях**, а не в осях камеры: телефон
не обязательно держать строго вертикально — наклон вперёд-назад и завал вбок учитываются.
Направление «вверх» телефон шлёт с датчика ориентации перед каждым кадром
(`{"type":"pose","up":[x,y,z]}`); без датчика (видео, ноутбук) оно берётся из плоскости пола.
Камера смотрит в пол сильнее 50° (или в небо) — голос: «Поднимите телефон выше» → через 5 с ещё
раз → через 15 с «Остановитесь…» (и каждые 15 с, пока не поднимут).

*Г. Главная опасность* (`threat.py`). Не всё вокруг, а:
- **неподвижное в коридоре движения** (ближе 7 м) — то, во что врежешься, если идти прямо;
  стоишь на месте — всё равно предупреждает (можешь пойти); удаляешься — не опасность;
- **едущее/идущее**, если его траектория пройдёт рядом с тобой (**точка наибольшего сближения**
  ближе коридора + 0.6 м). Машина, проезжающая поперёк в 12 м, — не тревога.

Для каждой угрозы считается время до столкновения; **главная (`primary`) — с наименьшим**.
Она сменяется, только если новая заметно опаснее (а первую секунду — вдвое), чтобы звук не прыгал.
Объекты сбоку, стоящие машины вдоль тротуара и прочее — не угрозы и звука не дают.

**Фильтр мелькания.** Угрозой становится только то, что видно подряд — так отсекаются надписи
и тени на асфальте и ошибки глубины. Но на проверку уходит не больше четверти времени до
столкновения: препятствие в 6 м проверяется ~1.2 с (максимум 1.5 с), в 2 м — ~0.4 с, ближе 1 м —
сразу. Препятствия сбоку не звучат, но обводятся рамкой «на готове»: повернулся, и оно оказалось
впереди — угроза сразу, без повторной проверки. Ещё отбрасывается «человек»
в нижней части кадра у края — это рука снимающего.

*Д. Классы опасности* (поле `alert`, `threat.py`):

| alert | что | на экране | звук |
|---|---|---|---|
| `danger` | угроза: главная или едет на тебя | красный/жёлтый/зелёный по срочности | сигнал / тревога + голос |
| `warn` | едущая машина (до 20 м, «едет» держится ≥ 0.5 с; тревога `danger` — только ближе 15 м); человек/животное идёт к тебе или стоит на пути (до 13 м); человек/животное/машина сбоку ближе 6 м | оранжевый | один раз голосом |
| `info` | люди, животные, машины ближе 13 м | голубой | молчит |
| `none` | статичное сбоку, далёкие объекты | серый | молчит |

*Е. Обстановка* (`context.py`): **толпа** (4+ человека ближе 20 м) и **парковка** (3+ стоящих машины
ближе 20 м) — одна фраза вместо каждого объекта: «Толпа людей слева и впереди», «Внимание, парковка.
Зона повышенной опасности» (повтор каждые 30 с, пока на парковке). Включается, если держится 1 с,
выключается через 4 с. Пока толпа или парковка активна, люди / стоящие машины по одному не озвучиваются.

*Ж. Камера плохо видит* — сервер сообщает `too_dark` (темно) и `blurry` (размыто: резкость кадра
< 150 при обычных > 1500 — запотело, закрыто пальцем, вплотную к однотонной стене). Тогда, как и при
потере связи с сервером дольше 3 с, голос просит **остановиться**.

**Звук (телефон).** Сигнал — только о главной опасности.
- **Сигнал как парктроник** (`spatialAudio.ts`): громкий, 900–1250 Гц (динамик телефона плохо
  играет низкие), с той стороны, где опасность (HRTF). Чем меньше время до столкновения, тем чаще;
  меньше 0.9 с или ближе 0.8 м — **непрерывный тон** («стоп»). Тембр: препятствие / человек / транспорт.
- **Тревога** (двойной тон): что-то едет на тебя, но главная опасность — другое.
- **Вибрация** (`haptics.ts`): препятствие прямо на пути ближе 2 м — импульсы в такт сигналу,
  вплотную — непрерывно; что-то едет на тебя — двойной толчок.
- **Голос** (`announcer.ts`), по приоритету, одна фраза за раз:
  1. «Осторожно! Машина слева» — перебивает всё;
  2. новая главная опасность — «Препятствие впереди, 3 метра»; ближе 3 м и 1.5 м — одно число;
  3. камера плохо видит — смотрит в пол («Поднимите телефон выше», по нарастающей до
     «Остановитесь…»), темно или размыто («Остановитесь. Изображение размыто…», каждые 8 с);
  4. обстановка — «Толпа людей справа», «Внимание, парковка…»;
  5. `warn`-объекты — «Едет машина слева, 15 метров», «Человек идёт к вам справа, 6 метров»
     (каждый один раз; повтор — через 15 с или если стало серьёзнее);
  6. советы — «Поднимите телефон выше» (по датчику наклона телефона).

  Отдельно: нет ответов сервера дольше 3 с — «Нет связи с сервером. Остановитесь» (каждые 10 с).

  Пока голос говорит, сигналы приглушаются.

**Масштаб глубины по полу.** Модель глубины может ошибаться в масштабе в разы (в офисе завышала
расстояния в ~3.4 раза): тогда пол «уезжал» на 3 м вниз, не находился, и препятствия не
определялись вообще, пока в кадр не попадал человек. Теперь пол сам служит линейкой: телефон в руке
на высоте ~1.35 м (`camera_height_m`), масштаб подстраивается за первые кадры. Для видео с камеры
на другой высоте: `run_video.py --cam-height 0.4` (или `0` — не калибровать по полу).

> **Карта местности и маршрут** (`server/spatia/worldmap.py`, кнопка «Map»). Всё, что камера видит
> выше пола, наносится на сетку 10 см в земных координатах (курс — компас телефона, сдвиг — скорость
> ходьбы по полу) и остаётся на карте; не подтверждённое гаснет вдвое за 60 с, увиденный пол очищает
> клетку. Люди/машины на карту не пишутся, но мешают маршруту. При заданном курсе A* строит полосу
> 0.5 м (с запасом 0.15 м от препятствий) до точки в 6.5 м по курсу — в обход препятствий, в том числе
> тех, что уже вне кадра; сторона обхода берётся из смещения маршрута у препятствия. Экран «Map» —
> обычная карта 15 × 15 м с сеткой 1 м (не радар: не крутится с телефоном), вверх — направление курса,
> в центре стрелка-человек; препятствия появляются с первого кадра, то, что видно сейчас, подписано;
> **курс — жёлтая линия, маршрут — зелёная полоса**. Камера и звук под картой продолжают работать.
> Если сервер не перезапустили после обновления, на экране «Server outdated — restart it»
> (сервер сообщает свои возможности в `ready.features`).
> Ограничения: счисление пути копит ошибку (карта живёт минуты), без компаса карта не следит за поворотами.

> **Сигнал (парктроник)** — частота только по расстоянию, ступенями по 0.5 м (ритм ровный, без рывков):
> 6–4 м — редкий тихий (жёлтая рамка), с 4 м — красная рамка и чаще с каждым полуметром, < 1 м —
> один сплошной тон. Стерео: звук в том ухе, где препятствие. При обходе препятствие сбоку рядом
> (по карте, в том числе уже вне кадра) тихо тикает в своё ухо. Голос: «Chair, 6 meters» →
> «4 meters. Pass left» → «2 meters» (только метры, фактические на момент речи). Препятствие,
> уже известное по карте (видели сбоку), при повороте к нему — угроза сразу. Совет обхода на экране —
> ровно то, что прозвучало.

> **Иду / стою / поворачиваюсь** — по датчикам телефона (`sensors/motion.ts`): акселерометр (шаги) и
> скорость поворота по компасу (> 25°/с). Состояние видно в строке статуса. Оно меняет только то, что
> говорит голос, — сигнал и тревога от него не зависят. Иду — как обычно. Стою — один совет: «Chair,
> 2 meters. Pass left» или «No way around. Turn the phone slowly left or right». Поворачиваю телефон —
> то, на что навелась камера, **не называется**; голос ищет проход: «Clear, 40 degrees right. Go this way».
> Состояние и компас пишутся в запись сессии (`SPATIA_RECORD=1`), чтобы подбирать пороги по реальным данным.
> Телефон можно держать **горизонтально**: камера видит ~65° вместо ~40°, экран переходит в компактный вид.

> **Актуально (перекрывает описания ниже):** приложение и голос — **на английском**; режим один
> (переключателя «Подробно» нет); голосового ввода нет; «маячка» прохода нет. Голос: неподвижное
> препятствие на пути — с 5 м, люди / животные / группа людей — с 10 м, едущий транспорт — до 20 м;
> в каждой фразе есть расстояние («Chair ahead, 3 meters. Pass on the left»). Отклонение от курса —
> в градусах: «Turn left 40 degrees». Рамки: красный/жёлтый/зелёный — на пути, оранжевый — люди и
> транспорт, белый — остальное; в подписи буква стороны L / C / R.

**Без перегрузки: режимы «Кратко» и «Подробно»** (кнопка «Подробно» на экране, по умолчанию кратко).
Расстояние и направление передаёт сигнал, голос — только то, чего сигнал сказать не может.
Кратко: тревога «едет на тебя»; препятствие на пути ближе 4 м — один раз, с советом обхода, не чаще
раза в 5 с; едущая машина и идущий к тебе человек; парковка, толпа; камера в пол / темно.
Подробно: ещё дальние препятствия, «3 метра / полтора метра», объекты сбоку, группа объектов,
«Путь свободен». На записях с телефона: подробно 19–28 фраз в минуту, кратко 10–12.

**Режим осмотра.** Камера видит узко, поэтому перед препятствием часто «прохода не видно» — голос
просит медленно повернуть телефон. Пока человек стоит и поворачивает телефон, то, что попадает в
кадр, не считается новым препятствием на пути: сигнал тихий, названия не говорятся. Свободно в эту
сторону — «динь» по центру и «Здесь свободно, правее. Идите в эту сторону» (сторона — по датчику
поворота телефона). Осмотрел обе стороны на 60° — «Свободного прохода не видно. Попробуйте вернуться
назад». Осмотр кончается, когда проход найден, человек пошёл или прошло 30 с.

**Курс — куда человек идёт.** Без курса система знает только «что перед камерой»: обходя препятствия,
человек постепенно уходит в сторону. Кнопка «Задать курс» (или голосом «курс») запоминает, куда сейчас
смотрит телефон (датчик поворота). После этого: сторона обхода выбирается ближе к курсу (клиент шлёт
отклонение в сообщении `pose`, поле `course`); ушёл в сторону больше чем на 25° и путь свободен —
«Курс левее»; вернулся — «На курсе». Долгое нажатие — сброс. Курс — это направление, а не точка:
«дойти до двери» система не умеет (нет карты и распознавания дверей).

**Голосовые команды** (кнопка «Команда», одна фраза; Web Speech API — Chrome на Android): «курс»,
«сброс курса», «куда» (где курс), «что впереди», «подробно», «кратко», «повтори».

**Режим по умолчанию — «Помещение»** (на улице переключить кнопкой «Улица»): сервер при старте
грузит обе модели глубины. **Массивная группа объектов** (`cluster`): 6+ предметов/препятствий ближе
6 м — одной фразой «Массивная группа объектов слева», повтор раз в 30 с.

**Всё, что видно, — в рамках.** Кроме трёх зон (слева / на пути / справа) клиенту уходят все области
препятствий по глубине и все предметы детектора (id ≤ −100, `alert=info`): без звука, но сервер их
помнит ~3 с — повернулся к ним, и угроза включается без повторной проверки.

**Навигация по звуку.** Угол на препятствие в наушниках растянут втрое (камера видит всего ±20°),
тон сигнала выше, чем ближе препятствие. Со стороны свободного прохода звучит мягкий «маячок»
(восходящий «динь») — на него можно идти. Совет обхода всегда называет предмет: «Стул, обход справа».
Препятствие ушло с пути — «Путь свободен».

**Что за препятствие и как его обойти.**
- **Название.** Препятствие по глубине подписывается: предметом, который знает детектор (скамейка,
  стул, гидрант, дорожный знак…), иначе по форме — «Стена» (широкое и высокое), «Столб или дерево»
  (узкое и высокое), «Низкое препятствие», иначе просто «Препятствие».
- **Обход** (`guidance.py`, поле `bypass`). Проверяются **полосы** — параллельные проходы шириной
  с человека, сдвинутые вбок на 0.6–1.8 м (шаг в сторону и дальше прямо). Полоса годится, если рядом
  с препятствием в ней нет препятствий и **виден пол** (невидимое свободным не считается).
  Голос: «Стул впереди, 2 метра. Обход слева»; проход появился позже — сразу «Обход справа».
- **Стоишь перед препятствием** (оно не приближается 2 с): сигнал не выключается, но становится
  редким и тихим, вибрация молчит, а голос каждые 7 с подсказывает: «Обойдите справа» или «Прохода
  не видно. Поверните телефон влево или вправо»; появился проход — «Обойдите слева»; препятствие
  ушло из кадра — «Впереди свободно». Пошёл к препятствию — обычный сигнал сразу.
- **Удержание.** Подтверждённое препятствие на пути, пропавшее на пару кадров, держится 0.6 с.
- **Речь без задержек.** Фразы короче; новая главная опасность ближе 3 м перебивает второстепенную
  фразу; о приближающемся человеке — «Человек приближается слева», дальше только «Человек, 5 метров».

**Разобрать пропуск препятствия с телефона.** Запусти сервер с `SPATIA_RECORD=1` — кадры и наклон
телефона пишутся в `server/recordings/<время>-<сессия>/`. Потом:
`.venv/Scripts/python tools/run_video.py --video recordings/<папка> --dump` — тот же конвейер по
тем же кадрам, с размеченным видео.

Проверить, что и когда скажет голос, без телефона: `run_video.py --dump` пишет ответы сервера
по кадрам в `output/<имя>/frames.jsonl`.

**Связь (протокол v1, подробно — в `server/spatia/protocol.py`):**
- После подключения клиент шлёт `{"type":"hello","scene":"outdoor",...}`, сервер отвечает `ready`.
- Кадр — **бинарное** сообщение: 4 байта номера кадра + JPEG (~640 px, ~30 КБ). Перед ним —
  (если есть датчик) `{"type":"pose","up":[x,y,z]}`: ориентация телефона для этого кадра.
- Клиент шлёт следующий кадр **только после ответа** на предыдущий — очередь не копится,
  задержка минимальна, частота сама подстраивается под сеть.
- Ответ: `{"type":"result","seq":42,"obstacles":[{"kind":"person","cls":"person","distance":3.4,"zone":"center","bearing":-2.1,"in_path":true,"approach":1.1,"own_speed":0.1,"ttc":3.1,"moving":false,"threat":true,"primary":true,"alert":"danger","urgency":"medium",...}],"groups":[{"type":"crowd","zones":["left"],"count":5,"distance":4.2}],"hints":[]}`.
  Список отсортирован: сначала главная опасность. `kind`: `person` / `vehicle` / `animal` —
  по детектору, `obstacle` — по глубине (id −1/−2/−3 = слева / в коридоре / справа).
- У каждого клиента своя сессия (трекинг, калибровка); видеокарта обрабатывает кадры по очереди.

Типичные цифры на RTX 3050 Ti: обработка кадра ~60–90 мс, в браузере 6–12 кадров/с
локально; через туннель — меньше, зависит от сети.

## Если что-то не работает

| Проблема | Решение |
|---|---|
| `cloudflared: command not found` | Перезапусти VS Code целиком или запускай по полному пути (см. выше) |
| На телефоне `{"detail":"Not Found"}` | Не собран фронт или сервер запущен раньше сборки: `npm run build:web` и перезапусти сервер |
| Камера не запрашивает доступ | Адрес должен быть `https://`, не `http://` |
| «Переподключение…» на телефоне | Проверь, что сервер запущен и в логе есть «модели загружены» |
| `address already in use` | Сервер уже запущен в другом терминале |
| Очень медленно (1–2 к/с) | Нет CUDA: проверь `.venv/Scripts/python -c "import torch; print(torch.cuda.is_available())"` |
| Дистанции странные | Переключи Улица/Помещение; для точности задай `camera_fov_deg` в `config.py` под свой телефон |
| Нужно понять, почему была тревога | Запусти сервер с `SPATIA_DEBUG=1` — в лог печатается каждое «едет на тебя» со скоростями |
| `run_video.py`: «Не удалось открыть видео» | `test_video.mp4` не хранится в репозитории — укажи `--video путь` или `--video 0` |
| Нет звука | Звук включается только после нажатия «Начать»; проверь кнопки Звук/Голос, громкость, беззвучный режим iPhone |
| Голос по-английски / молчит | В системе нет русского голоса для синтеза речи — установи русский голос в настройках телефона (Синтез речи) |
