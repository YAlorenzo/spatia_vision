# SpatiaVision

Мобильный ассистент пространственной навигации для слабовидящих. Телефон снимает
окружение камерой, сервер находит препятствия и оценивает расстояние до них в метрах,
а телефон сообщает о них **пространственным звуком** (сигнал слышно с той стороны,
где препятствие) и **голосом** («Человек прямо, 3 метра», «Осторожно! Машина приближается слева»).

```
Телефон (браузер)                                   Сервер (ноутбук с GPU)
┌──────────────────────┐   кадр JPEG ~30 КБ        ┌──────────────────────────────────┐
│ камера → кадр 640px  │ ────────────────────────> │ Depth Anything V2 → глубина в м  │
│                      │      WebSocket /ws        │  ├ пол (RANSAC) → всё, что выше  │
│ 3D-звук (HRTF),      │ <──────────────────────── │  │  пола = препятствие (без класса)│
│ голос, рамки         │   JSON: препятствия       │ YOLO11 → люди, транспорт, животные│
└──────────────────────┘                           │  └ трекинг → скорость сближения  │
                                                   └──────────────────────────────────┘
```

## Быстрый старт

### Что нужно установить

| Что | Зачем | Где взять |
|---|---|---|
| Git | клонировать репозиторий | https://git-scm.com |
| Node.js 20+ | собрать фронт | https://nodejs.org |
| uv | Python и зависимости сервера | `winget install astral-sh.uv` |
| cloudflared | HTTPS-адрес для телефона | `winget install Cloudflare.cloudflared` |
| Видеокарта NVIDIA | желательно; без неё работает, но медленно | — |

> После `winget install` **полностью перезапусти VS Code / терминал**, иначе новые
> команды не найдутся. Если `cloudflared` всё равно не находится — запускай по полному
> пути: `"/c/Program Files (x86)/cloudflared/cloudflared.exe"`.

Все команды ниже — для **Git Bash** (в VS Code: панель терминала → `˅` → Git Bash).

### 1. Клонировать

```bash
git clone https://github.com/YAlorenzo/spatia_vision.git
cd spatia_vision
```

### 2. Сервер (один раз)

```bash
cd server
uv venv --python 3.12

# PyTorch с CUDA (для видеокарты NVIDIA):
uv pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
# ...или без видеокарты (будет ~1-2 кадра в секунду):
# uv pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu

uv pip install -r requirements.txt
cd ..
```

Модели скачиваются сами при первом запуске (YOLO11n ~5 МБ, Depth Anything ~100 МБ) —
первый старт сервера займёт минуту-две.

### 3. Фронт (один раз и после каждого изменения фронта)

```bash
cd mobile
npm install
npm run build:web      # собирает веб-версию в mobile/dist — её раздаёт сервер
cd ..
```

### 4. Запуск — два терминала

**Терминал 1 — сервер:**
```bash
cd server
.venv/Scripts/python -m uvicorn app:app --host 0.0.0.0 --port 8000
```
Ждём строку `[server] модели загружены, жду подключений на /ws`.

**Терминал 2 — туннель:**
```bash
cloudflared tunnel --url http://localhost:8000
```
В выводе будет рамка с адресом вида `https://какие-то-слова.trycloudflare.com`.

### 5. Открыть на телефоне

Открой этот `https://…trycloudflare.com` адрес в браузере телефона → **Начать** →
разреши доступ к камере. **Надень наушники** — звук объёмный, сторону лучше слышно в них.
Наведи камеру на людей, машины, деревья, стены — появятся рамки с расстоянием
(пунктир — препятствие без класса), внизу — ближайшее препятствие, зазвучат сигналы и голос.

Сверху:
- **Улица / Помещение** — выбирай под реальную сцену, от этого зависит модель глубины;
- **Звук / Голос** — включить/выключить сигналы и голосовые подсказки.

> На iPhone звук может не играть, если включён беззвучный режим (переключатель сбоку).

**Остановка:** `Ctrl+C` в обоих терминалах.

## Почему именно так

- **Камера в браузере работает только по HTTPS.** Поэтому нужен туннель, а не просто IP ноутбука.
- **Один адрес на всё.** Сервер сам раздаёт собранный фронт (`mobile/dist`), и фронт
  подключается к `wss://<тот же адрес>/ws`. Ничего настраивать не нужно, работает в любой
  Wi-Fi сети (в т.ч. университетской, где устройства не видят друг друга).
- **Адрес cloudflared меняется при каждом запуске** — просто открывай новый.
- **Изменил фронт** → `npm run build:web` в `mobile/` и обнови страницу на телефоне.
  Сервер перезапускать не нужно (кроме случая, когда `mobile/dist` не было при его запуске).

## Другие способы запуска

### На ноутбуке с веб-камерой (удобно при разработке фронта)

Изменения кода фронта применяются сразу, без пересборки.

```bash
# Терминал 1
cd server && .venv/Scripts/python -m uvicorn app:app --host 0.0.0.0 --port 8000
# Терминал 2
cd mobile && npx expo start --web
```
Открыть `http://localhost:8081` — фронт сам найдёт сервер на порту 8000.

### Фронт через `expo start --tunnel` (два туннеля)

Если нужен hot reload прямо на телефоне: запусти сервер и `cloudflared` как выше, затем

```bash
cd mobile
echo "EXPO_PUBLIC_SERVER_URL=wss://АДРЕС-ОТ-CLOUDFLARED.trycloudflare.com/ws" > .env.local
npx expo start -c --tunnel
```
и открой на телефоне адрес, который выдаст **Expo**. Адрес в `.env.local` придётся
обновлять при каждом перезапуске cloudflared.

### Только распознавание, без телефона

```bash
cd server
.venv/Scripts/python tools/run_video.py --live --video 0 --indoor        # веб-камера ноутбука
.venv/Scripts/python tools/run_video.py --live --video путь/к/видео.mp4   # любое видео
.venv/Scripts/python tools/run_video.py --video видео.mp4                # без окна → output/<имя>/
```
Окно: слева кадр с рамками, справа карта глубины (светлее = ближе). Выход — `q`.
Зелёная заливка — найденный пол, фиолетовая — препятствия по глубине.
В подписи рамки `d=` — расстояние по модели глубины, `g=` — по размеру объекта,
`->1.2m/s ttc 3s` — скорость сближения и время до столкновения, `MOVING` — едет сам.
Внизу — высота и наклон камеры, оценённые по полу.
Флаги: `--indoor` (помещение), `--hfov 70` (угол обзора камеры), `--show` (каждый кадр, без пропусков).

Без окна сохраняются `annotated.mp4`, `objects.csv` (дистанция каждого объекта на
каждом кадре) и `summary.json` (FPS, стабильность).

### Проверить сервер без фронта

```bash
.venv/Scripts/python tools/ws_client.py --video 0 --seconds 20
```
Шлёт кадры по тому же протоколу, что и телефон, и печатает частоту и задержку.

## Как это работает

**Распознавание (сервер).** Два источника препятствий:

*А. Всё статичное — по карте глубины, без классов* (`free_space.py`). Дереву, столбу
и стене название не нужно — важно, что это препятствие.
1. **Depth Anything V2 Metric** строит карту глубины сразу в метрах (модели Outdoor / Indoor).
2. Карта переводится в 3D-облако точек (угол обзора — по длинной стороне кадра, поэтому
   одинаково для вертикального и горизонтального телефона), **RANSAC** находит плоскость пола —
   заодно известны высота и наклон камеры. Если пол пропал из кадра (вплотную к стене),
   держится последняя найденная плоскость.
3. Всё, что выше пола на 0.25–2 м и ближе 7 м, — препятствие (включая ветки на уровне головы).
   Зоны — **в метрах**: коридор движения шириной 0.9 м прямо по курсу и полосы до 2 м по бокам.

*Б. То, что может двигаться, — детектором* (`detection.py`): люди, транспорт, животные.
1. **YOLO11n** + **ByteTrack** (стабильный ID между кадрами).
2. Расстояние: глубина внутри рамки (30-й перцентиль — отсекает фон) + **геометрия** по
   известной высоте (человек 1.7 м, машина 1.5 м). При расхождении вес смещается к меньшей
   оценке. По этим же объектам **автокалибруется** масштаб модели глубины.

*В. Движение* (`motion.py`).
- **Скорость пользователя** — визуальная одометрия по полу: точки асфальта отслеживаются между
  кадрами (оптический поток), и раз плоскость пола известна, их смещение переводится в метры.
  Плюс «голосование» по кажущемуся сближению неподвижных объектов. Так различаются «стою»,
  «иду вперёд» и «пячусь назад».
- **Собственная скорость объекта** = его сближение минус скорость пользователя. Если ты идёшь
  к стоящей машине — она не «едет»; отходишь назад — ничего не «приближается».

*Г. Главная опасность* (`threat.py`). Не всё вокруг, а:
- **неподвижное в коридоре движения** (ближе 7 м) — то, во что врежешься, если идти прямо;
  стоишь на месте — всё равно предупреждает (можешь пойти); удаляешься — не опасность;
- **едущее/идущее**, если его траектория пройдёт рядом с тобой (**точка наибольшего сближения**
  ближе коридора + 0.6 м). Машина, проезжающая поперёк в 12 м, — не тревога.

Для каждой угрозы считается время до столкновения; **главная (`primary`) — с наименьшим**.
Она сменяется, только если новая заметно опаснее (а первую секунду — вдвое), чтобы звук не прыгал.
Объекты сбоку, стоящие машины вдоль тротуара и прочее — не угрозы и звука не дают.

**Звук (телефон).** Только о главной опасности, всё остальное молчит.
- **Сигнал как парктроник** (`spatialAudio.ts`): громкий, 900–1250 Гц (динамик телефона плохо
  играет низкие), с той стороны, где опасность (HRTF). Чем меньше время до столкновения, тем чаще;
  меньше 0.9 с или ближе 0.8 м — **непрерывный тон** («стоп»). Тембр: препятствие / человек / транспорт.
- **Тревога** (двойной тон): что-то едет на тебя, но главная опасность — другое.
- **Голос** (`announcer.ts`): «Осторожно! Машина слева» — перебивает всё; новая главная опасность —
  «Препятствие впереди, 3 метра»; подошёл ближе 3 м и 1.5 м — одно короткое число.
  Объекты сбоку не озвучиваются. Пока голос говорит, сигналы приглушаются.

**Связь (протокол v1, подробно — в `server/spatia/protocol.py`):**
- После подключения клиент шлёт `{"type":"hello","scene":"outdoor",...}`, сервер отвечает `ready`.
- Кадр — **бинарное** сообщение: 4 байта номера кадра + JPEG (~640 px, ~30 КБ).
- Клиент шлёт следующий кадр **только после ответа** на предыдущий — очередь не копится,
  задержка минимальна, частота сама подстраивается под сеть.
- Ответ: `{"type":"result","seq":42,"obstacles":[{"kind":"person","cls":"person","distance":3.4,"zone":"center","bearing":-2.1,"in_path":true,"approach":1.1,"own_speed":0.1,"ttc":3.1,"moving":false,"threat":true,"primary":true,"urgency":"medium",...}]}`.
  Список отсортирован: сначала главная опасность. `kind`: `person` / `vehicle` / `animal` —
  по детектору, `obstacle` — по глубине (id −1/−2/−3 = слева / в коридоре / справа).
- У каждого клиента своя сессия (трекинг, калибровка); видеокарта обрабатывает кадры по очереди.

Типичные цифры на RTX 3050 Ti: обработка кадра ~60–90 мс, в браузере 6–12 кадров/с
локально; через туннель — меньше, зависит от сети.

## Если что-то не работает

| Проблема | Решение |
|---|---|
| `cloudflared: command not found` | Перезапусти VS Code целиком или запускай по полному пути (см. выше) |
| На телефоне `{"detail":"Not Found"}` | Не собран фронт или сервер запущен раньше сборки: `npm run build:web` и перезапусти сервер |
| Камера не запрашивает доступ | Адрес должен быть `https://`, не `http://` |
| «Переподключение…» на телефоне | Проверь, что сервер запущен и в логе есть «модели загружены» |
| `address already in use` | Сервер уже запущен в другом терминале |
| Очень медленно (1–2 к/с) | Нет CUDA: проверь `.venv/Scripts/python -c "import torch; print(torch.cuda.is_available())"` |
| Дистанции странные | Переключи Улица/Помещение; для точности задай `camera_fov_deg` в `config.py` под свой телефон |
| Нужно понять, почему была тревога | Запусти сервер с `SPATIA_DEBUG=1` — в лог печатается каждое «едет на тебя» со скоростями |
| `run_video.py`: «Не удалось открыть видео» | `test_video.mp4` не хранится в репозитории — укажи `--video путь` или `--video 0` |
| Нет звука | Звук включается только после нажатия «Начать»; проверь кнопки Звук/Голос, громкость, беззвучный режим iPhone |
| Голос по-английски / молчит | В системе нет русского голоса для синтеза речи — установи русский голос в настройках телефона (Синтез речи) |
